# SERVICE_1_CASE_001_COLUMN_CONFIRMATION_REENTRY_V1_MODULECONTRACT

Status: MODULECONTRACT
Date: 2026-07-10
Scope: CASE_001 column-confirmation packet to online owner reentry and confirmed-columns handoff.
Governing ADR: `docs/adr/SERVICE_1_CASE_001_COLUMN_CONFIRMATION_REENTRY_SCHEMA_ADR_V1.md`

## Contract verdict

This ModuleContract defines two fail-closed modules required before CASE_001 owner column confirmation can move from documented packet to online owner reentry and controlled `confirmed-columns.json` candidate.

```text
column_confirmation_packet.json
-> packet-to-question-bundle adapter
-> Service1QuestionBundleV1
-> owner answers / reentry read model
-> answers-to-confirmed-columns transformer
-> confirmed-columns.json candidate
```

This contract does not authorize computation, dry-run, runner, SaaS runtime, API/storage/worker, autonomous delivery, final diagnosis, or product-ready claims.

## Module 1: packet-to-question-bundle adapter

### Module name

```text
SERVICE_1_CASE_001_COLUMN_CONFIRMATION_PACKET_TO_QUESTION_BUNDLE_ADAPTER_V1
```

### Purpose

Convert the certified CASE_001 `column_confirmation_packet.json` into a `Service1QuestionBundleV1` suitable for owner online reentry.

### Inputs

| Input | Required | Contract |
|---|---:|---|
| `column_confirmation_packet` | Yes | Dict matching the physical CASE_001 packet: `packet_type=COLUMN_CONFIRMATION`, `status=NEEDS_OWNER_CONFIRMATION`, `questions[]`. |
| `case_id` | Yes | Stable case identifier for online reentry binding. |
| `tenant_id` | Yes | Tenant identifier; must be non-empty and safe for storage boundaries. |
| `intake_id` | Yes | Intake/session identifier. |
| `run_id` | Yes | Source run identifier for traceability. |
| `source_file_ref` | Yes | Original source file reference, e.g. `CASE_001_ventas_junio_2026_margin_leak.xlsx`. |
| `metadata` | No | Optional dict; must not override certified fields. |

### Output

`Service1QuestionBundleV1` with:

```text
schema_version: SERVICE_1_QUESTION_BUNDLE_V1
service_name: SERVICE_1
runtime_authorized: false
owner_confirmation_required: true
selected_next_question_ref: first required pending question
questions: 12 Service1QuestionV1 entries
```

### Question conversion rule

For every source question:

| Source packet field | Bundle field |
|---|---|
| `question` | `text` |
| `sheet_name` + `column_name` | `target_ref = case_001:<sheet_name>:<column_name>` |
| `required` | `required` |
| source constant | `source = column_confirmation_matrix` |
| ADR constant | `answer_type = confirm_column_role` |
| `question_id` | `metadata.source_question_id` |
| `answer_type` from packet (`owner_text`) | `metadata.source_answer_type` |

`question_ref` must be generated by the existing stable convention:

```text
service_1:<source_slug>:<target_ref_slug>
```

### Required metadata per question

```text
source_question_id
source_packet_type
source_packet_status
source_answer_type
sheet_name
column_name
case_id
source_file_ref
```

### Fail-closed behavior

Return a blocked/invalid result or raise a deterministic validation error if:

- packet is missing or not a dict;
- `questions` is missing or not a list;
- any question lacks `question_id`, `sheet_name`, `column_name`, `question`, or `required`;
- any generated `question_ref` duplicates another question;
- any required identity field is blank;
- packet `runtime_authorized` is true.

### Must not do

- Must not invent owner answers.
- Must not generate `confirmed-columns.json`.
- Must not run CASE_001.
- Must not execute computation/dry-run.
- Must not call runner, SaaS runtime, API/storage/worker, or delivery.

## Module 2: owner-answers-to-confirmed-columns transformer

### Module name

```text
SERVICE_1_CASE_001_OWNER_ANSWERS_TO_CONFIRMED_COLUMNS_TRANSFORMER_V1
```

### Purpose

Validate owner online answers against the question bundle and emit a controlled `confirmed-columns.json` candidate only when all required column meanings are present and unambiguous.

### Inputs

| Input | Required | Contract |
|---|---:|---|
| `question_bundle` | Yes | `Service1QuestionBundleV1` produced by Module 1. |
| `reentry_read_model` | Yes | `Service1CaseReentryReadModelV1` with owner answers. |
| `case_id` | Yes | Must match bundle/read-model case binding where present. |
| `source_file_ref` | Yes | Original source file reference. |
| `metadata` | No | Optional dict. |

### Output: blocked result

If incomplete or ambiguous:

```text
status: NEEDS_OWNER_INPUT
confirmed_columns_candidate: null
missing_question_refs: [...]
ambiguous_question_refs: [...]
runtime_authorized: false
reexecution_authorized: false
recalculation_authorized: false
```

### Output: candidate result

If all required answers are valid:

```text
status: CONFIRMED_COLUMNS_CANDIDATE_READY
confirmed_columns_candidate:
  schema_version: SERVICE_1_CASE_001_CONFIRMED_COLUMNS_V1
  service_name: SERVICE_1
  case_id: <case_id>
  source_file_ref: <source_file_ref>
  columns:
    - question_ref
      source_question_id
      sheet_name
      column_name
      confirmed_meaning
      owner_answer_raw
      validation_status: VALIDATED_OWNER_PROVIDED
  runtime_authorized: false
  reexecution_authorized: false
  recalculation_authorized: false
```

The candidate may be written to disk by a later TaskSpec, but this module contract only defines the shape and validation behavior.

### Validation rules

A required answer is valid only if:

- it is bound to an existing `question_ref` in the bundle;
- it is non-empty after trimming;
- it is not a circular restatement of the column name only;
- it is not an explicit unknown answer such as `no sé`, `unknown`, `n/a`, or equivalent;
- it comes from owner reentry evidence, not operator inference;
- the read model does not set runtime/reexecution/recalculation authorization true.

### Must not do

- Must not infer business meaning from column names.
- Must not accept operator-invented answers.
- Must not compute margin/cash/stock/reconciliation.
- Must not re-run CASE_001.
- Must not produce diagnosis or delivery.
- Must not authorize runtime/reexecution/recalculation.

## Cross-module invariants

- `runtime_authorized` is always false.
- `reexecution_authorized` is always false.
- `recalculation_authorized` is always false.
- `question_id` is source metadata, never the stable `question_ref`.
- `target_ref` uses `case_001:<sheet_name>:<column_name>`.
- `answer_type` uses `confirm_column_role`.
- `owner_text` is source metadata only.
- Incomplete answers keep CASE_001 in `NEEDS_OWNER_INPUT`.

## Acceptance test requirements

A later TaskSpec must include tests for:

1. converting all 12 CASE_001 packet questions into bundle questions;
2. rejecting packet `answer_type=owner_text` as bundle answer type while preserving it as metadata;
3. preserving all 12 `question_id` values as `source_question_id` metadata;
4. generating stable `question_ref` values from `case_001:<sheet>:<column>` target refs;
5. refusing duplicate question refs;
6. refusing missing required fields;
7. returning `NEEDS_OWNER_INPUT` when any answer is missing;
8. returning `NEEDS_OWNER_INPUT` when any answer is ambiguous or circular;
9. producing `CONFIRMED_COLUMNS_CANDIDATE_READY` only when all 12 required answers are owner-provided and valid;
10. proving no runtime/reexecution/recalculation flags become true;
11. proving no computation/dry-run/delivery side effects occur.
